## 合意済み改善案 01
- **次の5行動（予測順）を横に並べ、その各キャラの枠の直下に行動ゲージを付ける**。表示を一体化。ゲージだけ別の長いパネルにしない。
- ゲージは原作の行動ポイント／待ちを**説明する可視化**であり、新しいリアルタイムATBシステムに置き換えてはいけない。
- 回転や行動で順番が変わる可能性を考慮。5行動の予測精度、同じキャラが再登場した場合のゲージ、非確定性の表示は実装前の仕様確認事項。数値・順番を「確定」と誤表示しない。
- 妖怪ウォッチ2はHP、妖気、取り憑き等の情報をすでにかなり表示している。**行動順以外も何でも追加可視化する**方針ではない。既存UIをまず調べ、本当に欠ける情報だけ検討。
- 改善UIは原作準拠の計算エンジンと分離し、原作処理へ影響しないようにする。原作準拠版を比較基準に保つ。

## 最新承認のロードマップ
1. **調査＋基礎エンジン**：行動ポイント／行動順／サークルの関係を調べ、6体編成・前衛3体・行動管理・交代を最小限実装。BOT/ログで検証。
2. **自動戦闘**：性格・攻撃/妖術/回復/ガード・ピン・ステータス・ダメージ・勝敗。
3. **状態変化**：取り憑き・おはらい・サボり・スキル・魂・陣（閃光魂は例外）。
4. **必殺技・零式機能**：妖気、チャージ、つつき、G技、タイミング／代表的な戦術。
5. **原作準拠版の総合検証**：行動頻度・結果分布・再現可能なテクニックを研究資料／実際の原作挙動と比較。
6. **改善UI**：「次の5行動＋各ゲージ」を追加。独自ルールは最初から追加しない。
7. **オンライン1vs1**：Firebase Realtime Database等でルーム番号方式、学校iPad Safari・Googleサイト版を検証。同期、通信遅延、ゲスト側の見た目／停止に注意。
※これは技術上の依存を踏まえて順序入れ替え可。段階2以降でも**その機能の実装直前に必ず再調査**。

1. **実装直前に外部資料を再調査**。過去チャットや要約だけに頼らない。公式仕様、対戦研究、実プレイ動画、必要なら対立情報を比較。
2. 仕様文書に「公式確認済／対戦研究の有力説／未確認・仮説」を明示。数式、イベント順、境界条件、例外と参照URLを記録。
3. 実装。戦闘エンジン、表示、通信をなるべく分離。検証用ログ、再現可能な乱数シード、ユニットテストを持たせる。
4. 自動検証＋原作戦術に照らした検証＋**人間が見たときの自然さをAI自身がスクリーンショットや動画で確認**。テスト合格だけで美術合格と言わない。問題が見つかれば修正・再検証。
5. GitHubの開発ブランチへ根拠・コード・結果・未解決点を記録する。公開/mainへ無断反映しない。実機未検証は明確に言う。

## キャラ制作から得た必須QA
- ゲームに直接使えるデータ（PNG/スプライトシート/コード）が必要。**画像生成の綺麗な1枚絵だけを納品しない**。画像生成→後から分割、手描きSVGで高品質再現、コードでの簡易3Dは過去に品質不足。
- 基本は64×64前後のドット絵、控えめで可愛い顔、外形・チャームポイント優先。静止画の最終デザインは**アニメーションと同時に決める**。固定してから無理に動かさない。
- 待機／通常攻撃／被弾／背面攻撃／必殺技ループを少ないコマで演出。姿勢・重心・尻尾の根元・腕の本数・表情・ループ継ぎ目を実画像で見る。攻撃腕の描画は通常腕への追加ではなく差し替え（4本問題の再発防止）。
- 現在の赤猫は**雰囲気の仮採用、完成デザイン未確定**。1体目の制作工程が合格するまで2体目を試験しない。2体目は量産可能性のチェックに使う。
- 原作画像・抽出3Dモデル・音楽等の無断再配布や公開組込みはしない。新作はオリジナルキャラ・素材を基準にし、原作のゲーム画面・UI・名称の丸写しを避ける。

## GitHubと公開の運用
- GitHub Pagesは本人がスマホ・PCで試遊する開発用URLになり得る。**「Googleサイト版」= HTML/CSS/JavaScriptコードをGoogleサイトの埋め込み機能へ直接貼って、友達とオンライン対戦できる状態**。単にGitHub Pages URLを貼る意味ではない。
- 既存のGoogleサイト版・学校で動くもの・mainを勝手に上書きしない。最終的な貼り付けは本人の操作。貼り付け可能なコードの形式で納品する。
- 完全無料厳守。有料サービスの導入や課金を勝手に行わない。Firebase設定や秘密情報を公開コードへ書き込まない。
- ローカル会話内のリンク・画像は新チャットで継続して利用できるとは限らない。現物確認なしに「GitHubにアップ済み」「実機テスト済み」と言わない。
