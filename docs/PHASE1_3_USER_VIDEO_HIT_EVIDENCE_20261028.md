## コーディング設計側の外部参照
- [Game Programming Patterns — Event Queue](https://gameprogrammingpatterns.com/event-queue.html)：ホストが確定した事実と、その後に表示するタイムラインを別に管理し、イベントの処理時に変動してしまう「現在状態」へ依存しない。
- [MDN — requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)、[Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)：非表示タブ/iframeで更新が止まり得る。描画キューは信頼できる絶対経過時間から投影し、戦闘ルールは独立して動かす。現在の小規模な`setTimeout`境界更新は表示専用であり、ブラウザ非表示時は既存のキュー破棄へ従う。
- `presentation/action-choreography.mjs`と`ui/match-stage.mjs`は、**V2の既存確定`hitResults[]`を表示するだけ**。命中・HPを描画側で再計算しない。

## Phase 1.3 の変更（原作パリティは未完）
1. `choreographyFrame(plan,elapsedMs)`に**`hitIndex`, `currentHit`, `nextHitAtMs`**を追加。ヒットの順序・実際に実行された攻撃試行数・各ヒットのMISS/会心/ダメージ/HPを**ホスト確定V2結果からだけ**読み取る。予定ヒット数が4でもKOで1発で終了したら、その1発しか表示しない。
2. **ヒット間隔は「既存の試遊用impact表示区間を均等に分ける仮表示」**。本家の実際のヒット間隔を検証していないため`originalTimingVerified:false`相当と解釈し、**秒数が一致したと主張しない**。この実装では必殺ではなく、V2ヒット記録を持つ通常攻撃のみ順次表示する。
3. `ui/match-stage.mjs`の表示専用`sceneHitIndex`を追加。段階が進んだ際のみ必要な画面を再描画し、**そのヒットのMISS/数字と確定`hpAfter`**を表示。ヒット前は`hpBefore`。戦闘確定HPはホストのまま、場面終了後は実際の最新snapshotに戻る。
4. ゲスト通信のhost権威/ACK/seq、乱数、妖気、勝敗、原作の行動順を変更しない。技別の演出/原作再現は**Phase2/5で動画比較とセット**で行う。1試合目ひゃくれつ肉球の正確なヒット数は未確定なので、「この技を完全再現した」とは言わない。
5. `tests/action-outcome-v2.test.mjs`に**MISS→命中の順次表示、各ヒットでHP変化、KO後の幻のヒット防止**を追加。静的ルールの検証を迂回せず維持。
