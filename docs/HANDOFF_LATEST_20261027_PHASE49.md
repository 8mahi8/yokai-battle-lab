## プロジェクトの目的と合意

- 『妖怪ウォッチ2』の**1vs1オンライン対戦の体験**を学校iPad Safari上で再現し、友達と無料で遊ぶ。
- **本家と内部コード/計算式の完全一致は必須ではない。** 最重要は、**見た目・操作感・ゲーム体験・戦闘システム・読み合い**が本家にできるだけ近いこと。安直な独自改善より先に原作体験の再現を優先。
- 友達同士で短時間遊ぶゲーム。**育成を省略、双方同じレンタル6体**で開始。前衛3+後衛3、サークル回転・狙う/つつく・妖気・必殺技・Gわざ・おはらい・零式切替を使う。
- 初期版に**閃光魂は入れない**。ガチ勢のノーモーション必殺等は専用ボタンとして追加するのではなく、原作の演出中の表示保留/操作と行動順を再現した**自然な結果**として成立させる。
- 音声は不要。ミニマップ/ランキング/自動ログ収集など、依頼されていない追加機能は不要。
- **学校公開はGoogle Sites埋め込みコード欄へHTML/CSS/JSを直接貼る**（GitHub Pages URL埋め込みではない）。GitHub Pagesは必要なら個人試遊用。
- **GitHub main、既存Google Sitesに貼った学校版、既存Drive配布、Firebase本番RTDB/Rulesを無断更新しない。** 開発ブランチで実装・テストし、別名で候補版を作る。
- 「任した」は調査→実装→テスト→スクリーンショット確認→GitHub保存を主体的に進めてよいという意味。新チャットで同じことを聞き直さない。

## 実装済み（Phase45〜49）

- **開発基盤**：`content/rental-roster.mjs` に6体能力と学校プレイ用性格/サボりのデータを分離。 `presentation/action-catalog.mjs` と `action-choreography.mjs` で行動種別ごとの **予備動作→効果発生→戻り**を読み取り専用の演出として設計。ゲームのダメージ/ターン順/通信は演出から絶対に変更しない。
- **Phase46**：`engine/combat.mjs`の戦闘イベントに窓の移動に依存しない`eventId`を付与。`ui/battle-vfx.mjs`と`ui/match-stage.mjs`へ接続、重複イベント描画の抑制、HPを命中フレームで更新する表示層、攻撃/妖術/回復/とりつき/ガード/サボりの異なるCSSモーション。背景のiframe停止から復帰したら古い演出を破棄。
- **Phase48**：学校Friends版でサボりが`enableLoafing:false`相当だった問題に対応。6体`loafChance`学校**暫定値3,2,1,3,2,5%**（原作確率不明）。`ui/passive-feedback.mjs`が戦闘エンジンで実発動した`おせわ/どひょうぎわ/まえのめり`等を正しい対象と共に表示。
- **Phase49**（本人動画を見て実装）：`ui/match-stage.mjs`と`lab/yw2-layout.css`で、必殺時は戦場上画面全域を切り替える**オリジナルSVGキャラ大写し＋専用背景＋技名**、ピン対象に**円形リング/十字照準**、キャラそばに**良悪とりつき状態マーク**。 `content/presentation-labels.mjs` でレンタル6体の技名をデータ化。動画から公式の素材/ゲームアセットはコピーしていない。
