# Phase50｜学校Friends対戦の戦闘演出キュー耐性（2026-10-27）

## 起点と優先順位
Phase49 は本人提供の原作映像観察からカットイン/ピン/状態アイコンまで完了したが、`ui/match-stage.mjs` は `latestBattleCue` 一件だけを処理していた。Firebase通知がまとまる、またはSafari iframeが表示再開すると、確定済みの複数アクションが同一スナップショットに含まれても最後しか演出しない／新しい演出が古い演出を遮る問題があった。

本Phaseは**演出の取りこぼし/遮断を減らす基盤修正**であり、原作の可変行動ウェイト・同期表示保留や技演出自体の原作精度を完成させたという主張ではない。

## 実装
- `ui/battle-cue-sequence.mjs` を新規追加。既存`eventId`を使い、`action/special/poke`のうち前回IDより新しい確定イベントを時系列で抽出。スキルなどの非対象イベントを架空の攻撃にしない。
- `ui/match-stage.mjs` にレンダラ専用FIFOを追加。予備→効果→戻りの1行動中、新しいイベントを受けても通常は現在の行動演出を中断せず、次を待たせる。
- 視覚キューの上限は4件。大量の差分到着 (`skipped>0`) は古い表示をまとめて捨て最新の意味ある行動へ同期する。この時、何手も前のHPを「命中前HP」と誤って見せない。
- 初回join時は既存イベント履歴を再生しない。ページが非表示になった場合は未再生キューと現在の演出を廃棄し、正規スナップショット表示へ戻る。
- 演出中の入力は従来どおり。ホストの2600ms間隔、勝敗/RNG/行動順/妖気/ Firebase通信・本番設定には変更なし。
- `tests/phase50-batched-action-cues.test.mjs` にまとめ受信・再受信・ログ窓スライド・バースト時のスキップ・新試合ID巻戻しの6テスト追加。既存ブラウザ QA が必殺／自動スキルとタッチを継続検証。

## 原作忠実度に関して
- 原作対戦の表示保留とノーモーション必殺は単なる演出キューでは再現できない。両視点ごとの表示確定境界/技硬直/入力権利を解析してから別Phaseで実装する。
- 元の動画は実況の編集があり、秒数を原作の正確なモーション値と断言しない。カタログ値は試遊のまま。
- 外部参考：[たくトンボ「対戦の基礎テクニック」](https://note.com/tombow_yw/n/n1e4cf179d2d9)、[MDN Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)。
