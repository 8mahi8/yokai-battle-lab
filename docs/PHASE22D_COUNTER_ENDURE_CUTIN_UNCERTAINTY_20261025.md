## 2. 2026年・2024年プレイヤーの原作資料を再調査した内容
1. [たくトンボ：知って得する対戦の基礎テクニックと仕様](https://note.com/tombow_yw/n/n1e4cf179d2d9)。「モーション中に自分が輪回転や必殺チャージを進めても、相手側にその見た目が反映されるのはモーション終了時」という説明。従って**ノーモーション必殺はチャージがゼロ時間で完了する技ではなく、相手に途中経過が見えない視覚/演出の戦術**。
2. 同じ記事のカウンター解説：相手必殺のカットイン中に「チャージ完了！」が出た場合、その瞬間に相手が見せていた面に当たる。間に合わなければ通常はカットイン終了から約0.5秒後に出ている面。**我慢を2つ消費した例外**は「カットイン中に相手が出していた面」に当たるという記述だが、**その間に相手がサークルを動かした場合、カットイン開始・途中・終了のどのフレームで固定されるかは定義していない**。
3. [マグロ『妖怪ウォッチ2対戦の全て』（2024-10-13）](https://note.com/uzoumzou_nanoha/n/n2fb6ae41559c)：とりつき・おはらい・相手必殺等のモーションがノーモーションの機会、タップ式やG技のタイミングに注意。サークル2回回転/カウンターの細部を提示。戦術の**存在と条件の参考**であってROMの実行順フレームではない。
4. [2023年コミュニティQ&A](https://detail.chiebukuro.yahoo.co.jp/qa/question_detail/q13280480983)：とりつきテキストが表示された瞬間から始めるのでは遅い場合があり、行動モーションが**始まると同時に仕掛ける**ことの説明（低信頼の補助意見）。開始時刻を原作のmsへ変換できない。
5. [たくトンボ：サ終後の対人ステップ](https://note.com/tombow_yw/n/naf0778efab26)：サドンデスで全体必殺のカウンターがあり得ること、前衛全滅に伴う強制回転への注意。原作の対象・終盤仕様の定性情報。

**ソースとコードの境界**
- **高信頼の定性ルール**：ノーモーション=相手に途中演出が見えにくい、早期/後期カウンターの対象の種類、2我慢による例外の存在。
- **未証明の定量/確定瞬間**：各モーションのミリ秒、cut-in終了+厳密500ms、チャージ閾値、連続2回転の内部判定境界、2我慢例外の「カットイン中」どの瞬間が対象か、3回以上の回転、ネットワーク遅延。
- 既存の800ms・500ms仮想タイミングは**研究用固定入力**。本家そのもののルール定数ではない。

## 3. 今回発見した研究実装の弱点と修正
既存`engine/counter-window.mjs`は、**2我慢例外でカットイン中に相手が回転していても、カットイン開始時の面 `frontAtStart` を本家の固定対象であるかのように採用**していた。これはソースが保証していない。研究用HPダメージを誤って「原作のカウンター回避再現済」と扱うリスク。

**修正した点**：
- `engine/counter-window.mjs`：`cutin.frontChangedDuringCutin` を追加し、**カットイン中だけ**対象側の前衛変更を記録。2我慢例外かつ**カットイン終了後にチャージ完了**かつ回転履歴ありの場合、返却・pending hitの`uncertainty.code='two-endures-cutin-front-lock-time-unverified'`を付ける。元の`frontAtStart`は**候補のひとつ**として保持するが、原作での確定対象と呼ばない。0回/終了後の回転だけなら従前の検証可能なケースを維持。
- `engine/combat.mjs`：対象が未確定と識別されたときは、ゲージ消費・イベントの時系列・キューは維持しつつ、**HP減算は実行せず**`counter-hit-indeterminate`に保存。これは**研究オプションのみ**に限定。3回以上の輪回転を未確定とする既存処理も保持。
- `tests/counter-window.test.mjs`：元の1ケースを確定範囲だけに限定し、カットイン中の回転・元の面に戻す回転・カットイン終了直後の回転をそれぞれ追加（**純粋テスト3件増**）。曖昧さを明確に検出。
- `tests/combat-counter.test.mjs`：元の2我慢のHP適用を**安定したcut-in面**の条件だけに限定。追加の**統合1件**で、実際に相手Bがcut-in中に回転→2我慢→遅いカウンターを実行してもHPを推測で適用せず、未確定イベント1件だけを返すことを検証。

**重要**：通常の`createMatchProtocol`は`researchCounterTiming`/`researchWheelCoalescing`などの未確認研究オプションを受け取らず、今回の変更で**通常対人のHP・チャージ・サークル回転仕様は変わらない**。
