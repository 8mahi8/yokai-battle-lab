# Phase26｜試遊優先の妖気仮数値（2026-10-25）

## ユーザー判断と全体方針
2026-10-25、本人は「原作で確定しない数値を無理に探し続けるより、調査結果から**ひとまず仮値で遊べるようにして、実際に友達と試遊してから調整**」を選択した。この決定で、以前の研究保留を「永久に通常対戦では妖気が増えない」というゲーム上の不自然な仕様として放置しない。

- **原作の再現が最終目標なのは不変。** ただし根拠の不足する数値でも、**試遊版と明確に表示した仮値**ならプレイアビリティと面白さを先に評価してよい。3DS内部数値・正規原作一致と主張しない。
- 友達同士1vs1、課金なし、両側同じ6体、閃光魂初期OFF、Google Sitesへコード全文貼り付け。ページ再読み込み/ブラウザ再起動で以前の対戦へ復帰する機能は**不要**。対戦中の同期だけ守る。
- Phase1〜25で実装済の戦闘/soul/つつく/通信/画面を**全て再利用**。研究用の実測比較器は変更せず、**試遊用オプションにだけ**仮値を渡す。

## どこを変更したか
- **一元調整**：\`engine/playtest-soul-tuning.mjs\` にプレイ用暫定数値をまとめた。今後、本人の試遊結果を聞いたらまずここを修正する。別の報酬エンジンや設定UIは作らない。
- **戦闘本体再利用**：\`engine/combat.mjs\` に \`playtestSoulTuning\` boolを追加。既存の \`createSoulSystem\` / \`pokeInput\` / \`step\` とその上限処理を再利用する。
- **本命SupabaseのGoogle Sites版だけON**：\`lab/sites-embed-supabase-entry.mjs\` のホスト作成で \`createMatchProtocol({battleOptions:{playtestSoulTuning:true}})\`。旧Firebaseバックアップと原作研究テストで \`createMatchProtocol()\` を使う場合は従来の挙動を維持。
- **表示**：\`tools/build-sites-supabase.mjs\` のHTMLヘッダーに「攻撃・妖術・つつくの妖気は調整用仮値」と明記。
- ホストオプションは真偽値だけ。ブラウザから送られる操作コマンドでSoul増加量を自由指定はできない。ホストのseedと初期オプションは従来どおりJournalに保存される。

## 今回の仮値（今後試遊で変更する初期案）
| 操作 | 1回の妖気 | 根拠の区分 |
|---|---:|---|
| 自分が攻撃以外を行った後（ガード、とりつき、回復、サボり） | **+5** | [RCのプレイヤー実験](https://note.com/ricosama0726/n/n14710bbe446c)の報告と既存正規ホスト一致。完全な全状況再現は未保証 |
| 自分の通常攻撃後 | **+8** | 仮値。現在の+5と同程度〜やや多めから開始。命中しなかった場合も基礎値は付く（これも仮） |
| 自分の攻撃妖術後 | **+8** | 仮値。通常攻撃と後で独立調整できる |
| サボり中または悪いとりつき中の敵へ攻撃が命中 | **追加+4** | [攻略大百科](https://gamepedia.jp/youkai-yw2/archives/1482)に定性的な回復増加の記述のみ。数値は仮。ミスには付かない |
| 零式つつく成功時の妖気吸収 | **最大35** | 仮値。敵の残ゲージ、味方前衛の受け手の空き容量までに制限。現在の試遊版は確率の仮選択を入れず、成功時は常に吸収を試みる。原作では他の結果もある。受取先は既存研究用実装と同じ「最初の生存前衛（先頭）」を再利用。受取先・抽選・量は原作未確定 |

**重要:** 通常攻撃+8、妖術+8、弱い敵への追加+4、つつく最大35という数値は、**元の妖怪ウォッチ2から確認された正確な妖気量ではない**。面白さを試して修正するための初期案。勝手に原作再現成功とみなさない。妖気上限、チャージ中断、G技隣接3体消費、一対象一回Pokeなどの既存仕様は維持。
