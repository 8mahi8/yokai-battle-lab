## 3. 今回した作業（Phase21D-C3→Phase22A／2026-10-25）
**全体のどこ:** 原作PvPの妖気回収に関する原作実戦記録 → Phase21Dの既存つつく実装・Soulゲージシステム → Phase22の必殺連射戦術 → Phase23オンライン同期・24学校iPad Safari/Google Sites直接コード貼り付け。

**原作対人の新資料:** [ゲーム動画ともとも、2014年11月9日公開の妖怪ウォッチ2通信対戦](https://www.youtube.com/watch?v=bLt5uujW9kU)の説明では4戦目は「つっつくで妖気を奪われてからのカツオブシ斬りで勝敗が決まった」とある。[2020年の対戦編成研究](https://game-cap.com/youkaiwatch2/data/make1539.html)の編成文には「とりつき→吸収→トホホ必殺→吸収→ジバS必殺→大ガマ必殺→百々目鬼G必殺」と連続戦術が記載。**複数妖怪への回収を使う戦術が想定されていたことの定性資料だが、動画フレームや実機の妖気量・配分ルールは未計測**。原作にない補正や受取先を正規ホストへ採用しない。

**実装＋受け入れ:** 既存戦闘研究機能を統合する`tests/phase22-poke-soultimate-cycle-lab.test.mjs`を追加。オリジナルレンタル6体・研究専用`createCombat({researchPokeSoulTransfer:100,researchSpecialEffects:false})`だけで、敵B1への悪いとりつき→零式つつく完了→A1妖気フル→**通常モードで必殺1回目**→別敵B2をつつく→A1妖気フル→**必殺2回目**という依存関係を実行。追加で**自軍サークルを回して受取者をA1からA2に切り替え、別の妖怪A2が2発目の必殺を出す研究シナリオ**も通した。既存研究fixtureの「前衛先頭が受け取る」規則を使うが、これは原作確定の分配則ではない。すでにつついたB1へは再つつく不可。零式のG技は本人＋隣接2体が満タンでなければ発動不可。**100ポイント・味方先頭A1・12タップはいずれも原作確定値でなく研究fixture**。通常設定ではつつく妖気報酬`unresolved`で連射できず、正規ホストに研究用回収量を渡すと拒否される。**戦闘の標準挙動は無変更**。

**テスト:** [Node442/442 + Chromium研究ブラウザ QA](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40113587363) PASS、[通常2席対戦画面QA](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40113516815) PASS。GitHub最終更新コミットのCIも実行して確認。[Firebaseローカル2ブラウザ従前PASS](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40111904332)だが、今回の変更は`tests/`と`docs/`のみのためクラウド本番・学校Safari・Google Sites直貼りを検証したとは言わない。

**詳しい調査と注意:** [Phase21D-C3→22A通信対人の歴史資料と研究必殺連射QA](./PHASE21D_C3_PHASE22A_PVP_POKE_SOULTIMATE_RESEARCH_20261025.md)。旧Phase21D-C2、21D-B2の根拠を重複実装せず再利用。

**変更先と君の操作:** GitHub `feat/phase1-action-circle-lab-20261023`の研究テスト・docsのみ変更。main、既存Googleサイト版、本番Firebase、課金、追加アカウントに変更なし。**君の操作はまだ不要**。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
