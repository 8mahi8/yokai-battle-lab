## 0. 絶対仕様（ゴールは一つ）
学校の古いiPad Safariで友達と遊ぶ、**妖怪ウォッチ2の対人戦闘ルールをまず忠実に再現した**完全無料のブラウザ1vs1。既存戦術が成立することを原作資料・実際の検証と照合した後だけ独自改善する。初期は双方同じオリジナルレンタル6体、**閃光魂なし**。本家に寄せた**上3vs3戦場／下6体メダルサークル＋4コマンド**構成。ゲームの単一HTML/CSS/JSをGoogle Sitesの「コードを埋め込む」へ**直接貼る**（GitHub Pages URLのiframeではない）。`main`・既存Googleサイト版・本番Firebaseは勝手に変更しない。完全なブラウザ再起動後の自動復元はユーザー不要の判断。

## 3. 今回した作業（Phase21D-C2／2026-10-25）
**全体のどこ:** 原作PvPの妖気回収（Phase21D）→ `engine/poke-input.mjs`・`engine/combat.mjs`・`engine/match-protocol.mjs` の既存つつくと正規ホスト → Phase22の必殺連射。研究を重複実装せず、原作と照合できる観測ケースを追加した。

**新たに確認した根拠:** [任天堂公式『YO-KAI WATCH 2』説明書（PDFページ66、0基点65）](https://csassets.nintendo.com/noaext/image/private/t_KA_PDF/manual-3DS-Yo-Kai_Watch_2_Fleshy_Souls)に、零式つつくを成功させた場合の効果として**相手のSoul Meterを減らす**ことが明記。必ず妖気減少になるわけではなく、妖気量・味方の受取人・効果抽選率は記載なし。[公式ゲームサイト](https://www.youkai-watch.jp/yw2/game/game06.html)もツボで違う結果を示す。競技者報告は妖気回復に本人の行動や魂が影響するため、**単純なゲージ差をつつくだけの効果とは判定できない**。旧攻略Wikiに後衛0.75倍等の記述が検索索引上あるが、原文確認不十分につき未実装。

**実装:** `engine/phase21d-poke-soul-trace.mjs`追加。観測前後の**両側12体の妖気ゲージ**とターゲットを厳密に検査、敵の減少量と味方の増加候補を分離。ほかのイベントが混在した場合は判定保留。仮に対象が減って味方が同量増えても、**誰が受け取るか・原因がつつくかは公式未確認**と返し、報酬を捏造しない。研究用純粋関数で、正規対戦の妖気移動やG技コストは無変更。

**オンライン回帰QA:** `tests/phase21d-poke-soul-trace.test.mjs`に前後比較・入力検査など7件追加。`tests/phase21d-pvp-poke-host-qa.test.mjs`に実際の正規2席ホストでの **相手サークル回転による中断／零式→通常への切替による中断**、一度も成功していない場合はつつく権利が残ること、Journal決定的再演の2件追加。

**受け入れテスト:** [Node **438/438＋Chromium研究QA PASS**](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40112911940)。[対戦画面・指操作Chrome CI](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40112911977)も動作検証。研究モジュール追加時の[Firebase Auth+RTDBローカル実2ブラウザCI](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40112703789)がトリガーされているが、これは**学校実機Safari・クラウド本番と別**。原作3DSでの完全数値照合は未実施。

**実装/根拠の詳細:** [Phase21D-C2：任天堂資料、12体ゲージの比較器、正規ホスト中断テスト](./PHASE21D_C2_POKE_GAUGE_OBSERVATION_AND_HOST_QA_20261025.md)。[21D-B2/C1の既存報告](./PHASE21D_BC_RATE_INTERVAL_AND_POKE_HOST_20261025.md)も維持。

**変更範囲/君の操作:** GitHub開発ブランチ`feat/phase1-action-circle-lab-20261023`のみ。**main、Google Sitesへの直接コード埋込版、本番Firebaseを変更していない。課金0。現在、君の操作は不要。**

## 4. 次にする作業（Phase21D-C3 → Phase22）
1. **21D-C3:** つつくが本家対人で「妖気吸収」を出した画面の、敵・味方それぞれ12体の前後変化、サークル操作・他妖怪の行動・自然回復・魂装備を時刻順に検証。実際の対象妖気減少量、受取先、発生確率、999ダメージの競技ルールを確認する。**公式説明書では未数値**なので、これを確認するまでは正規ホストの報酬を仮値でONにしない。
2. **21D-B3:** 攻撃・妖術・後衛の自然妖気蓄積の本家実測。RCの非攻撃行動+5と24条件は保持するが、旧Wikiの後衛0.75倍など未確認の定数は原作正式扱いしない。
3. **21C残:** 開幕の登録前衛権・同着優先順位は実機で数値と行動順が見える比較資料待ち。Flash Soulは初期OFF。
4. **Phase22→23→24:** 必殺連射／ノーモーション／カウンターの原作戦術 → オンライン同期の安定 → 古い学校iPad Safari＋Google Sitesへ**自己完結HTML/CSS/JSを直接貼り付ける**。育成や独自戦術、公開版を無断変更しない。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
