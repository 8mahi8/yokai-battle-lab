学校の古いiPad Safariで友達と遊ぶ、**妖怪ウォッチ2の対人戦闘ルールをまず忠実に再現した**完全無料のブラウザ1vs1。既存戦術が成立することを原作資料・実際の検証と照合した後だけ独自改善する。初期は双方同じオリジナルレンタル6体、**閃光魂なし**。本家に寄せた**上3vs3戦場／下6体メダルサークル＋4コマンド**構成。ゲームの単一HTML/CSS/JSをGoogle Sitesの「コードを埋め込む」へ**直接貼る**（GitHub Pages URLのiframeではない）。`main`・既存Googleサイト版・本番Firebaseは勝手に変更しない。完全なブラウザ再起動後の自動復元はユーザー不要の判断。

## 3. 今回した作業（Phase21D-C3→Phase22A／2026-10-25）
**全体のどこ:** 原作PvPの妖気回収に関する原作実戦記録 → Phase21Dの既存つつく実装・Soulゲージシステム → Phase22の必殺連射戦術 → Phase23オンライン同期・24学校iPad Safari/Google Sites直接コード貼り付け。

**原作対人の新資料:** [ゲーム動画ともとも、2014年11月9日公開の妖怪ウォッチ2通信対戦](https://www.youtube.com/watch?v=bLt5uujW9kU)の説明に、**4戦目は「つっつくで妖気を奪われてからのカツオブシ斬りで勝敗が決まった」**とある。映像のゲージフレームや12体有効妖気は抽出できておらず、**具体的な回収量・相手妖気減少・受取妖怪は不明**。[2020年の速射編成コメント](https://game-cap.com/youkaiwatch2/data/make1539.html)でも「つつくによって妖気を溜めるジバS」と言及がある。公式説明書の妖気吸収効果は以前から確認済み。**推測の受取先や数値を正規ホストに採用しない**。

**実装＋受け入れ:** 既存戦闘研究機能を統合する`tests/phase22-poke-soultimate-cycle-lab.test.mjs`を追加。オリジナルレンタル6体・研究専用`createCombat({researchPokeSoulTransfer:100,researchSpecialEffects:false})`だけで、敵B1への悪いとりつき→零式つつく完了→A1妖気フル→**通常モードで必殺1回目**→別敵B2をつつく→A1妖気フル→**必殺2回目**という依存関係を実行。すでにつついたB1へは再つつく不可。零式のG技は本人＋隣接2体が満タンでなければ発動不可。**100ポイント・味方先頭A1・12タップはいずれも原作確定値でなく研究fixture**。通常設定ではつつく妖気報酬`unresolved`で連射できず、正規ホストに研究用回収量を渡すと拒否される。**戦闘の標準挙動は無変更**。

**テスト:** [Node441/441 + Chromium研究ブラウザ QA](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40113351666) PASS、[通常2席対戦画面QA](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40113351604) PASS。GitHub最終更新コミットのCIも実行して確認。[Firebaseローカル2ブラウザ従前PASS](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40111904332)だが、今回の変更は`tests/`と`docs/`のみのためクラウド本番・学校Safari・Google Sites直貼りを検証したとは言わない。

**詳しい調査と注意:** [Phase21D-C3→22A通信対人の歴史資料と研究必殺連射QA](./PHASE21D_C3_PHASE22A_PVP_POKE_SOULTIMATE_RESEARCH_20261025.md)。旧Phase21D-C2、21D-B2の根拠を重複実装せず再利用。

**変更先と君の操作:** GitHub `feat/phase1-action-circle-lab-20261023`の研究テスト・docsのみ変更。main、既存Googleサイト版、本番Firebase、課金、追加アカウントに変更なし。**君の操作はまだ不要**。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
