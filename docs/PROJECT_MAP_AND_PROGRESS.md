## 0. 絶対仕様（ゴールは一つ）
学校の古いiPad Safariで友達と遊ぶ、**妖怪ウォッチ2の対人戦闘ルールをまず忠実に再現した**完全無料のブラウザ1vs1。既存戦術が成立することを原作資料・実際の検証と照合した後だけ独自改善する。初期は双方同じオリジナルレンタル6体、**閃光魂なし**。本家に寄せた**上3vs3戦場／下6体メダルサークル＋4コマンド**構成。ゲームの単一HTML/CSS/JSをGoogle Sitesの「コードを埋め込む」へ**直接貼る**（GitHub Pages URLのiframeではない）。`main`・既存Googleサイト版・本番Firebaseは勝手に変更しない。完全なブラウザ再起動後の自動復元はユーザー不要の判断。

## 3. 今回した作業（Phase21C-C＋21D-A／2026-10-25）
**全体のどこ:** 原作の研究 → Phase21C 初手の行動権・同着 → Phase21D 妖気ゲージ取得規則。既存 `engine/phase1.mjs`/`engine/opening-first-action-audit.mjs`と `engine/soul.mjs`/`engine/combat.mjs` の研究機能を再利用。**通常のホスト戦闘ルール・UI・通信は未変更**。

**今回:** [マグロの対戦研究](https://note.com/uzoumzou_nanoha/n/n2fb6ae41559c)により、マッチング時の初期前衛の権利より、その後前衛が獲得した行動権が優先される定性的なケースを再確認。ただし各キャラの対戦中有効素早さ・登録時リング・実際のwait/フレームが揃わないため、架空の原作一致データは作らず**21C数値と同着を保留**。

**21D-A実装:** [RCの実測研究](https://note.com/ricosama0726/n/n14710bbe446c)「非攻撃の本人行動後+5」を限定的に扱う研究比較器 `engine/phase21d-soul-observation.mjs`を追加。本人が攻撃以外の行動をしたケースについて、追加妖気発生源がないことを明示できた**観測データだけ**+5仮説と比較。攻撃・妖術・零式つつく、他妖怪の妖気、装備や自然回復に影響された観測は`indeterminate`（判定不能）とし、未確認の妖気量を勝手に導入しない。Soul本体・正規対戦の既定は無変更。`tests/phase21d-soul-observation.test.mjs`に9テスト、実際の正規ホストのガード/攻撃イベントとJournal再演の照合を追加。

**テスト結果:** [Node417/417＋Chrome研究画面](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40109349907) PASS、[対戦画面とPointerEvent](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40109349911) PASS、[Firebase Auth+RTDBローカル2ブラウザ](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40109310363) PASS。これらは原作3DS・本番Firebase・学校Safari・Googleサイト直接埋込の実測ではない。

## 4. 次にする作業（Phase21D-B/Cと21C観測ゲート）
1. **Phase21D-B:** 攻撃/妖術による妖気増加、自然回復と魂装備の寄与を原作で区別できるデータを探す。値が確かめられた分だけ既存 `researchSoulRecoveryMode` と比較し、正規ホストへの統合は別途QA。
2. **Phase21D-C:** 零式つつくで妖気を受け取る妖怪、量、敵から奪うのか、1回限りかを原作で検証。Phase7の研究専用`researchPokeSoulTransfer`を事実として採用しない。必殺連射の再現は回収量の検証後。
3. **残るPhase21C:** 対戦前に登録した前衛・開始時前衛・サークル操作履歴、12体の有効すばやさ、最初の数行動がわかる原作観測ケースが必要。同着時の現行A優先は仮で、Flash Soul初期OFF。
4. **その先:** Phase22ノーモーション・カウンター→ Phase23オンライン通信→ Phase24実機学校iPad SafariとGoogleサイト単一HTML**コード直接貼り付け**。原作完全一致・学校公開完成は宣言しない。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
