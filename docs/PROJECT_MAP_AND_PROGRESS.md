## 3. 今回した作業（Phase22B／2026-10-25）
**全体のどこ:** 原作の操作の型（Phase21/22）→ 戦闘エンジン`engine/soul.mjs`/`engine/charge-input.mjs` → 正規2席ホスト`engine/match-protocol.mjs` → 既存戦闘画面`ui/match-stage.mjs` → Phase23 Firebaseのゲスト追従/Phase24学校iPad SafariとGoogle Sites直接HTMLコード貼り付け。今回ゲームロジックの改変は不要で、足りなかった**正規ホスト全チャージ・キャンセル・消費・再試行**の受け入れテストを実装。

**原作根拠:** [ゲームエイト『必殺技の使い方と妖気ゲージの回復方法』](https://game8.jp/youkai-watch2/504498)によれば必殺は妖気満タン後に「わざ」を選び、4種類「まわせ」「打て」「なぞれ」「あわせろ」のタッチチャージを行う。[攻略大百科・Gわざ](https://gamepedia.jp/youkai-yw2/archives/1873)と[同・Gゲージ条件](https://gamepedia.jp/youkai-yw2/archives/5657)は発動者と固定輪左右隣接2体が満タンである必要を示す。ミニゲームの具体的閾値・ランダム割合・操作時間、G威力等は**未証明の研究値**であり、その仕様まで原作一致したとは言わない。

**今回追加した実装:** `tests/phase22b-canonical-soultimate-qa.test.mjs`（新規**9テスト**）。4チャージ種を実ホストの正規`chargeInput`イベントで完走する4件、チャージ中のウォッチ切替・本人を後衛へ回す各取消2件、固定輪A6が後衛にいてもG消費3体となる1件、100ゲージをガード行動で自然獲得して必殺→空になる1件、ホストAと相手Bが同時に独立チャージして完走する1件。最後のタッチコマンドを再送しても妖気を二重消費しないこと、空ゲージで連続発動不可、`makeStageView`/`soultimateReadiness`の「わざOK」と正規ホスト可否の一致、`replayMatchJournal`を全ケースで確認。

**注意:** 通常100妖気テスト以外の連続性チェックは`soulCapacity:5`・強制ガードの**明記されたテスト専用レンタル能力**を使用する。正規2席ホストAPIには追加デバッグ入力も機能追加もなし。原作なら5妖気で必殺が打てる、4チャージの研究入力の指定座標・ステップ数が元ゲームと完全一致する、といった主張はしない。Phase22Aの`researchPokeSoulTransfer:100`による研究連射は従来どおり**正規オンラインでOFF**。

**検証:** [Node **451/451 PASS（新規9/9）**](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40116853158)。[元ゲーム風画面＋Chrome指操作](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40116853197) PASS。前回の[Firebase Auth+RTDBローカル2ブラウザQA](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40111904332)もPASS（**今回クラウド本番・学校実機で再試験した意味ではない**）。原作3DSのチャージフレームや現実の学校iPad Safari・Google Sites直貼りは引き続き未実測。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
