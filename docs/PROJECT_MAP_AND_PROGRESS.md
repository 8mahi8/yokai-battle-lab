## 0. 絶対仕様（ゴールは一つ）
学校の古いiPad Safariで友達と遊ぶ、**妖怪ウォッチ2の対人戦闘ルールをまず忠実に再現した**完全無料のブラウザ1vs1。既存戦術が成立することを原作資料・実際の検証と照合した後だけ独自改善する。初期は双方同じオリジナルレンタル6体、**閃光魂なし**。本家に寄せた**上3vs3戦場／下6体メダルサークル＋4コマンド**構成。ゲームの単一HTML/CSS/JSをGoogle Sitesの「コードを埋め込む」へ**直接貼る**（GitHub Pages URLのiframeではない）。`main`・既存Googleサイト版・本番Firebaseは勝手に変更しない。完全なブラウザ再起動後の自動復元はユーザー不要の判断。

## 3. 今回した作業（Phase21C-B／2026-10-25）
**全体位置:** 原作・対戦競技者の資料 → `engine/phase1.mjs` の94行waitと `engine/opening-priority.mjs` のマッチング前衛研究 → **新** `engine/opening-first-action-audit.mjs`（原作動画の初手比較だけの独立ツール）。通常の対戦ホスト・通信・UIは**変更なし**。

**今回の成果:** 原作研究の追加照合により、**マッチング時の登録前衛と戦闘開始時に見えるサークルの前衛を区別する必要**を再確認。マグロ・RC・たくトンボの具体的な初期行動権記述をPhase6の既存実験と照合。正確な登録前衛補正量・同着順・内部乱数は現状根拠が不足しており、原作にない値を勝手に追加しない。

**実装:** `auditFirstAction({teams,visibleStartOffsets,matchingStartOffsets,wheelMovedSinceRegistration,observedFirstActor})`を追加。両軍6体の有効素早さと94行初期waitから「観測初手が取り得る候補か」を条件付きで判定。**マッチング後に回転した、または登録前衛と可視前衛が違う場合は必ずindeterminate（判定不能）**とする。同着は未確認のため全候補を可能扱いする。原作への一致・不一致を乱数や未知の優先権を推測して宣言しない。**研究比較専用**で、正規ホストやGoogleサイト版に統合しない。

**テスト:** `tests/phase21c-first-action-audit.test.mjs`で同速・絶対的速さ差・モデルに矛盾する観測・登録前衛変更・全回転復帰・ID対応・非破壊・異常入力の**8ケース**を追加。[408/408 Node＋研究Chromeテスト](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40108875411)成功。対戦画面Chromeは[別CI](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40108875421)。前の開発コミットではGitHub runner側Chromium起動が一時失敗したが、同じコード系列の後続研究CIは再実行で成功。原作3DS実機・学校Safari・Google Sites直接埋込・Firebase本番はいずれも未検証。

**根拠と再利用資料:** [Phase21C-B研究証拠・比較器](./PHASE21C_B_OPENING_RIGHT_OBSERVATION_AUDIT_20261025.md)、[Phase21C-A待ち値表全数照合](./PHASE21C_INITIAL_ORDER_SOURCE_AUDIT_20261025.md)、[既存Phase6開幕研究](./PHASE6_OPENING_FLASH_QA_20261023.md)。本文の資料は「コミュニティ実測／競技者観測／原作不明」を区別。原作実機の完全一致と混同しない。

**変更範囲:** `feat/phase1-action-circle-lab-20261023`のみ。main/既存Googleサイト版/本番Firebaseは変更なし。費用0、閃光魂初期OFF。君の操作はいま不要。

## 4. 次にする作業（Phase21C-C → 21D）
1. **21C-C 原作3DS初手観測:** 両軍の有効素早さ・マッチング登録前衛・開始時サークル・回転履歴・初手の妖怪IDと次の数行動を記録したオリジナル原作試験を収集。新研究比較器を適用し、具体的に矛盾したときだけコード修正を検討。
2. **初期行動権・同着優先:** Phase6の`turn===0`限定の研究仮説と、他の妖怪が動いた後も初期前衛の権利が残り得るという競技者の例を、ROMまたは観測で検証。A優先タイブレークはまだ**仮**。未検証数式は通常ゲームに投入しない。
3. **21D 妖気回収:** 既存のPhase4/7/魂エンジンを確認し、攻撃・妖術・零式つつき・後衛入替ごとの実際の増減数値と必殺連射戦術を原作資料と照合。
4. **Phase22 → 23 → 24:** 対人テクニック（ノーモーション・カウンター）→ 1vs1通信安定化 → 学校SafariとGoogleサイトへの**単一HTML直接コード貼り付け**。回復・毒・技威力の仮値、閃光魂OFFは保留維持。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
