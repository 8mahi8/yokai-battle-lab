## 0. 絶対仕様（ゴールは一つ）
学校の古いiPad Safariで友達と遊ぶ、**妖怪ウォッチ2の対人戦闘ルールをまず忠実に再現した**完全無料のブラウザ1vs1。既存戦術が成立することを原作資料・実際の検証と照合した後だけ独自改善する。初期は双方同じオリジナルレンタル6体、**閃光魂なし**。本家に寄せた**上3vs3戦場／下6体メダルサークル＋4コマンド**構成。ゲームの単一HTML/CSS/JSをGoogle Sitesの「コードを埋め込む」へ**直接貼る**（GitHub Pages URLのiframeではない）。`main`・既存Googleサイト版・本番Firebaseは勝手に変更しない。完全なブラウザ再起動後の自動復元はユーザー不要の判断。

## 3. 今回した作業（Phase21D-B／2026-10-25）
**全体のどこ:** 原作妖気のソース研究 → Phase4/7既存の`engine/soul.mjs`・`engine/combat.mjs` → **新しい研究用の数値根拠比較** `engine/phase21d-soul-rate-evidence.mjs` + `tests/phase21d-soul-rate-evidence.test.mjs`。ゲームの標準ホスト動作は変えていない。

**今回の成果:** [RC妖怪ウォッチ2の隣接妖気回復魂の実験](https://note.com/ricosama0726/n/n14710bbe446c)に記録された「Grade1〜4の威力/妖気型別のゲージ上限」8群×隣接えんら魂0/1/2個＝**24件の実測報告**を独立固定データとして転記。候補式`floor(5 + N*capacity/50)`（1行動の回復量）から満タンまでの行動数を算出し比較。**23件一致・1件不一致**。Grade2威力型・ゲージ130・えんら魂2個では報告14行動に対して仮式13行動、対して同じ容量130のGrade3妖気型では報告13行動。**容量だけの一般式であると断定できない**ことを積極的にテストに残した。元データを仮式に合わせて書き換えない。

**新規実装:** データ表と`predictResearchRecharge`/`comparePublishedRechargeEvidence`（研究用）。候補式の返値は`originalParityVerified:false`。実験内容が異なる攻撃・妖術・通常時間回復、零式つつくに同じ値を流用しない。既存の`researchPokeSoulTransfer`、通常キャラの妖気上限、正規対戦既定設定は**変更しない**。通信対戦のつつくは二次資料上「ダメージ／妖気吸収／999ダメージ」の3種類という情報も記録。ただし選択確率・妖気移動量・受取人は未確定。

**検証:** `tests/phase21d-soul-rate-evidence.test.mjs`に観測全24件、唯一の不一致、同容量の差、未確定表示、値の境界、入力検査、正規ホストの従来ガード妖気+5とJournal再演の**7ケース**追加。[Node **424/424＋Chromium研究QA PASS**](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40111340391)、[Chromium対戦ステージ操作 QA PASS](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40111340383)、[Firebaseローカル2ブラウザ QA PASS](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40111304091)。3DS実機の独立追試・学校iPad Safari・Google Sites直貼りは未検証。

**詳細:** [Phase21D-B妖気24件・候補式と唯一の不一致](./PHASE21D_B_SOUL_RATE_TABLE_AUDIT_20261025.md)、[Phase21C-C / 21D-A](./PHASE21C_C_21D_A_SOUL_EVIDENCE_20261025.md)。以前の研究成果や仮値を黙って正式ルールへ昇格させない。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
