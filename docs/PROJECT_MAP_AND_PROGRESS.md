## 0. 絶対仕様（ゴールは一つ）
学校の古いiPad Safariで友達と遊ぶ、**妖怪ウォッチ2の対人戦闘ルールをまず忠実に再現した**完全無料のブラウザ1vs1。既存戦術が成立することを原作資料・実際の検証と照合した後だけ独自改善する。初期は双方同じオリジナルレンタル6体、**閃光魂なし**。本家に寄せた**上3vs3戦場／下6体メダルサークル＋4コマンド**構成。ゲームの単一HTML/CSS/JSをGoogle Sitesの「コードを埋め込む」へ**直接貼る**（GitHub Pages URLのiframeではない）。`main`・既存Googleサイト版・本番Firebaseは勝手に変更しない。完全なブラウザ再起動後の自動復元はユーザー不要の判断。

## 3. 今回した作業（Phase21B／2026-10-24）
**全体位置:** `engine/phase1.mjs`（既存サークル3秒制限）→ `engine/match-protocol.mjs`（2席ホストの原作ルール）→ `network/firebase-match.mjs`（ゲスト通知）→ `ui/match-stage.mjs` / `lab/firebase-match-stage.html`（日本語表示）。**戦闘ルール＋オンラインUIの接続**であり、学校サイト公開ではない。

**今回の成果:** 原作の公式対戦で確認できた3秒回転制限を、開発中の正規対戦`createMatchProtocol`の標準設定`rotationCooldownMs:3000`へ変更。旧モデル比較だけは明示的`rotationCooldownMs:0`。Phase21Aのホスト専用モノトニック時刻とJournal完全再演を再利用。ゲストが回転を拒否された際、ホストが通信受信したこととゲームに反映したことを区別し、`サークルはまだ回せません（あと約X秒）` を両座席で表示。古い通信形式の操作結果不明を成功扱いしない。原作の二度回転ターゲット遅延はPhase5の研究のみで、まだ標準実装していない。

**検証:** [Node396/396＋旧研究Chrome](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40103884449) PASS、[本家風ステージChromeと10タッチ試験](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40103884464) PASS、[実Chrome2席・Firebase Auth+RTDBローカルエミュレーター](https://github.com/8mahi8/yokai-battle-lab/actions/runs/40103884476) PASS（33ルール権限試験、1回目成功→直後2回目拒否＋画面の理由表示＋両席盤面不変＋通信切断復帰）。今後`engine/**`の変更で2席実ブラウザQAが必ず走るようワークフロー改善。[Phase21Bの詳細・証拠](./PHASE21B_OFFICIAL_WHEEL_AND_GUEST_ACK_20261024.md)。

**重要な留保:** 3秒ルールは**原作の公式ルール通信対戦**の出典あり。無料対戦や3DSのフレーム単位の硬直まで一致したとは言えない。学校iPad Safari・実Firebase本番・Googleサイト直接コード貼付は未検証。

**変更範囲:** GitHub開発ブランチのみ。main/既存Googleサイト/本番Firebaseは変更していない。

## 4. 次にする作業（Phase21C → 21D）
1. **21C 行動順・初期待ち時間の再現度**: Phase1に既存の94行速度表、初期前衛の乱数範囲、前衛復帰時の待ち値、同着時の処理の原作一致を資料・動画で比較する。仮の同値順位を原作確定ルールとして扱わない。**研究を作り直さず、具体的に矛盾が見つかったら修正。**
2. **21D 妖気回収の実測研究**: 攻撃・妖術・零式つつく・後衛入替での妖気の獲得数／条件を照合。必殺連射の戦術が成立するか確認。未確定の数値は仮定しない。
3. **Phase22 PvP技術**: Phase5ノーモーション必殺・二度回し対象処理・カウンター窓を、原作映像と照合して正規対戦に統合。その後Phase23のオンライン安定化、Phase24の学校iPad/Googleサイト直貼りHTMLへ。
4. **継続保留:** 回復基礎式と毒HP継続量、オリジナル6体の必殺技個別威力は未確定。Flash Soulは初期版OFF。

## 5. 次フェーズへ進む条件と設計逸脱を防ぐルール
- **原作再現 → 対人戦術 → オンラインの安定 → 学校Googleサイト**の順を守る。画面装飾、独自ATB、次の5行動予測（UI標準ではOFF）、閃光魂、育成、ランキング、リプレイ、観戦は**現在のスコープに入れない**。
- 何かを「再現済み」と言うには、①資料と根拠の確信度、②戦闘コード、③再現テスト、④原作との比較ケースの4つが必要。**Node全件PASSは元ゲームとの一致を示さない**。
- 新機能の前に既存 `docs/` と `engine/` `tests/` を検索する。同じ研究を2回始めない。
- 少なくとも「原作確認済」「有力な非公式研究」「仮値」「未着手」を区別して記載。
- このファイルの **「今回」→「次」→「全体の設計のどこ」** を毎回作業終了時に更新し、GitHubとチャットの両方で報告する。大きい変更の際はここへ関連コード・run URL・次の受け入れ条件を残す。
