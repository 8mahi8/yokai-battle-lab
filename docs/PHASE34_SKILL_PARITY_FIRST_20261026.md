# Phase34-A｜原作の「自動スキル」と「演出中の相手画面固定」を分けて再現（2026-10-26）

## 本人との合意・再確認
本人：「ノーモーション必殺はゲーム本体の仕様を逆手に取る技術。まず本体を原作に近づけたい」→「今のキャラにはスキルあるの？」→「スキルをしっかり調べて実装できればノーモーションにもつながる」。
**スキルを作っただけでノーモーション完成とは扱わない**。『妖怪ウォッチ2』の「固有スキル」は戦闘中自動発動する特殊能力であり、通常技・妖術・とりつき・必殺技とは別。一方、ノーモーション必殺が生じるのは「相手の行動/とりつき等の**モーション演出中はサークルやチャージの見た目の更新が相手側で保留される**」ため。自動スキル発動時のテキスト表示と、各モーションの表示保留条件を無条件に同一視しない。

## 今回調べた原作の具体例・確度
- [攻略大百科：妖怪ウォッチ2全スキル191件](https://gamepedia.jp/youkai-yw2/skills)：「スキル」は多数の受動特性を含む。種類や対象範囲を憶測で作らない。
- [攻略大百科：原作のスキル表示とアクションの違い](https://gamepedia.jp/youkai-yw2/archives/1446)：スキルは戦闘で自動発動する特別能力、通常攻撃・妖術・とりつき・必殺技とは別。
- [ジバニャン「まえのめり」攻略大百科](https://gamepedia.jp/youkai-yw2/skills/3033)／[Mt. WildwoodのYW2個別ページ](https://mtwildwood.net/ja/yw2/yokai/jibanyan)：**敵を気絶させると、ちからとようりょくが2段階上がり、その妖怪の5行動分続く**。再発動は期間を更新、無限重複しない。対象は撃破した**本人**。日本語概要と詳細データを区別。
- [花さか爺「おせわ」攻略大百科](https://gamepedia.jp/youkai-yw2/skills/2904)／[Mt. WildwoodのYW2個別ページ](https://mtwildwood.net/ja/yw2/yokai/elder-bloom)：**サークルで両隣の妖怪に、自分の行動終了時に最大HPの2%の回復（最低1）**。スキル保持者は後衛でも有効。同じ配置で2人の保持者に挟まれると2回分回復。**スキル所持者自身が回復対象という意味ではない**。
- [攻略大百科「いっせん」](https://gamepedia.jp/youkai-yw2/skills/2893)／[Mt. Wildwoodクリティカル計算](https://mtwildwood.net/critical-hits.php)：**クリティカル率上昇**という効果の種類は確認。だが個々の「いっせん」が出目へいくつ足すかは十分に確認できていないため、**試遊用仮補正 +5/99**。これは本家確定値と呼ばない。
- [対戦プレイヤーによるモーション/ノーモーション研究](https://note.com/tombow_yw/n/n1e4cf179d2d9)：表示反映タイミングの研究根拠。発動スキルの表示が**必ず**相手画面を止めるか、各スキルに対応する固有フレームがあるかは未確認。そうした架空のフレームを追加しない。

## 実装した事実（3系統だけ。残りはまだ未実装）
- `engine/skill-effects.mjs` を追加。外部依存のない固定効果の検証と仮値管理。学校の旧Safariを考慮して `Object.hasOwn()` は使わない。
- `engine/combat.mjs` の元の全6体レンタルのうち：
  - **あかねこ**：`skill:'momentum'`（原作「まえのめり」型）。自分の通常攻撃または必殺技で敵をKOしたとき、ちから/ようりょくに+2段階の強化を**次の5回の本人行動**へ付与。連続KO時に5回を更新し、重複倍掛けしない。既存のダメージ算式のstatStageへ付与する。現時点で特殊な必殺技ごとに複雑なstat倍率を上乗せする処理は未完成。
  - **すずかぜ**：`skill:'sharpCrit'`（原作「いっせん」型）。既存の原作参考クリティカル判定へ **+5/99の試遊用仮値**。この数値を原作仕様だと明言しない。
  - **ほたる**：`skill:'care'`（原作「おせわ」型）。味方6枚の円形隣接位置を使う。本人ではなく**隣の妖怪が行動した後**、最大HPの2%（最低1）の回復を与え、最大HPを超えない。保持者自身が**控えにいても有効**、KO保持者は効力停止。
- 既存のレンタル **こもれび・いしもり・くろがねのスキルはまだ未割り当て**。原作調査を続け、効果・対象・発動条件を確認してから割り当てる。なにもないのに「全6人のスキル完成」と報告しない。
- `enableRentalSkills` で従来の研究ルールを壊さず比較可能。通常の `playtestSoulTuning:true` とオンライン版ではデフォルト有効、従来 `createCombat()` の独立研究対照ではデフォルト無効。戦闘の乱数は既存ホストのseedだけで判定される。
- 追加の自動スキル効果は**既存のKO/攻撃/所有ターン/状態判定でのみ発動**。Supabase経路、戦闘のclock、全体演出時計、ブラウザの隠し操作、対象ターゲットを新設しない。
- 勝敗/操作側の確定状態 `snapshot.game.skillBoosts` を含み、戦況イベント `{type:'skill',actor,label,kind}` として双方へ配信する。UIの妖怪選択欄でスキルの種類/期間を確認でき、イベント欄でも発動が読める。
- **イベント欄表示はまだ原作の演出フレームではない**。スキルの発動表示そのものが opponent-visible freeze を開始するとは推測しない。先に前衛/チャージの表示を固定する別のプレゼンテーション層を統合する。
