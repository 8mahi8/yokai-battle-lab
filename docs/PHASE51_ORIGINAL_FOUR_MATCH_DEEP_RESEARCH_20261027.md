# Phase51｜原作実戦動画を再現仕様の基準にするための深掘り研究（2026-10-27）

## 立場・現状
ユーザーから『妖怪ウォッチ2』の対戦**4試合**の録画が提供された。**動画内でプレイヤーができること・考えること・双方の画面で見えることをブラウザで再現できる**のがゴール。「4種類のチャージ」「5種類のおはらい」を単に列挙して実装しただけで完成とはしない。**まず調査、拙速な本体修正をしない**。公開の原作映像/スクリーンショットをGitHubへ転載しない。

### 観察エビデンスの境界
- 実フレームを読めた4試合の**1試合目のみ**：[MATCH01](./ORIGINAL_PVP_VIDEO_20261027_MATCH01_OF04.md)。提供者の別撮影録画を読んだ過去の[Phase49](./PHASE49_USER_SUPPLIED_ORIGINAL_PVP_VIDEO_REVIEW_20261027.md)も利用。
- **2〜4試合目は4ファイル登録済だがPython/containerの実行時ClientErrorによりMP4抽出が不能**。受信を「視聴完了」と書かない。相手視点・指の実軌跡も未測定。
- 今回は既存の第1試合のサンプル画像（約00:16 / 00:32 / 00:44）を**再び実際に目視した**。重要な観察と限界：
  - 約00:16：上画面の短い文は「おはだがしわくちゃになって まもりが大ダウン」、下画面の丸い紫UIには「連打！」と見える。**操作画面が戦闘と並列表示**。この数コマだけで連打の用途・タップ回数・成功前後は確定しない。
  - 約00:32：上画面に橙/赤の**円形照準+中心十字**、下画面には相手妖怪をレンズで狙う別画面。**ピン選択時に上画面と下画面が別の役割を担う**。プレイヤーの指そのものは録画に映らない。
  - 約00:44：ひゃくれつ肉球の大きな専用カットイン中、**下画面のウォッチサークルは引き続き表示**。カットインが最前面固定のブラウザモーダルで上下両方を隠すUIでは原作の見え方と異なる。ここから操作可能性までは断言できない。
  - 『0勝0敗』等の大きな字幕や端末通知は録画主/環境のオーバーレイ。**原作UIと誤認してコピーしない**。
- タイムコード間隔の粗い静止画のみから指の軌跡・入力閾値・無操作時間・2台画面差を確定しない。

## 調べ直した外部一次・準一次資料
1. **Nintendo公式説明書** §19/§20 (PDF p.57, p.63–64): https://csassets.nintendo.com/noaext/image/private/t_KA_PDF/manual-3DS-Yo-Kai_Watch_2_Fleshy_Souls 。上画面・下画面と前衛3/後衛3、満タン妖気→選択→タッチ→必殺、悪とりつきを受けたメンバーを**後衛に移して**おはらい、狙うレンズ、Gわざは発動者+両隣の3妖気を消費。PDFの該当ページ画像を実際に確認。
2. **必殺のミニゲーム説明**：攻略大百科 https://gamepedia.jp/youkai-yw2/archives/1482 。「まわせ」「なぞれ」（同じ図形を3回）「打て」（**飛んでくる黄色い玉**を白色にする）「あわせろ」（数字へ針を3回）。**現在の6固定玉とは見た目・操作が異なる可能性が高い**。
3. **おはらい**：Game8 https://game8.jp/youkai-watch2/505163 は「つぶせ、連打、こすれ、まわせ、斬れ」の5つで、特に「斬れ」は**鎖のヒビ**、「連打」は**光る部分**が効率化要素と記載。攻略大百科 https://gamepedia.jp/youkai-yw2/archives/1397 は「後衛に下げ→下画面左下のおはらい→対象妖怪→指示動作」。単純な5モードの名前一致では不十分。
4. **待ち順**：データ解析/実機検証の記述あるMt.Wildwood https://mtwildwood.net/turn-order.php 。最小Waitの前衛が次の行動、YW2の多くの技のAction wait=3、入替直後=3×速度重み。**『行動順モデル』と『壁時計の秒数』は別**。
5. **回転タイマー**：Mt.Wildwood https://mtwildwood.net/yokai-wheel.php 。YW2でタイマーを伴う戦闘は4秒回転ウィンドウと記載するが、**どの戦闘が対象かは未解明**と明記。ページに別掲の「onlineで4秒+5秒待ち」は**YW1欄**なので、これをそのままYW2対戦の確定仕様として流用しない！
6. **チャージ中の妨害**：Mt.Wildwood https://mtwildwood.net/soultimate-charge.php 。被ダメージ・会心・ヒット累積でキャンセル確率が変わる。現状では式の一部が実装されているが、全特殊技の補正確認が必要。
7. **対人戦のモーション・非同期表示**：競技プレイヤーたくトンボ(2026-08-03) https://note.com/tombow_yw/n/n1e4cf179d2d9 。特に「相手側のサークルの見た目はアニメの終わりまで保留」「モーション中に必殺チャージするノーモーション」「カウンター必殺と受け側面固定」「おはらいによる交代、完了モーション、隣接回復魂」「行動ポイント」等。実戦家の記述を**原作コード証明とは区別**。
8. Nintendo公式の通信対戦紹介 https://www.youkai-watch.jp/yw2/communication/com02.html 。オンライン/PvPは別の観点で調べる。

## 最重要な「やってはいけない勘違い」
- 「チャージUIに4つの選択肢がある」≠「4種類を原作どおり入力できる」。
- 「おはらい成功で状態が消える」≠「おはらい中に上画面が見える／戦況を読める／完了モーションで駆け引きできる」。
- 「ステート受信時にFIFO演出する」≠「対戦相手には前のサークル位置がモーション終了まで表示される」。
- 「行動Wait表は元データベース参照済」≠「行動間の時間2600msが原作と同じ」。
- 「データ上でひゃくれつ肉球が複数ヒット」≠「録画と同じ順にキャラ移動・ヒットエフェクト・数字が発火」。
- 「4試合送信済」≠「4試合を視聴済」。
- **Mt.WildwoodでYKW1とYKW2の説明欄を取り違えないこと。**

## 現実的な調査ステップと定義
1. **映像アクセスの復旧**：ファイル自体は受領済み。動画解読環境が利用可能な新セッション/ツールに変わったら、V2〜V4を小間隔で読み直し、原作側のUIスクリーンショットはPRIVATE、時刻と観察テキストだけGitHubへ。再送は不要な限り要求しない。
2. **シーン・操作ラベル付け**：試合別の表に`clipTime,eventType,actor,target,topScreen,bottomScreen,gestureVisible,lifeOrSoulChange,screenLock,confidence,source`を入れる。操作のはじめと終わりは1秒未満間隔でキャプチャ、必要な箇所のみ手動フレーム精査。指そのものが無ければジェスチャー方向・必要回数を確定しない。
3. **ゲーム側を同じ順序で再生**：同じ入力操作を実装に与え、DOM/UIの上画面・下画面の変化と対照表を作る。ソース動画のキャラや技・編成が現行レンタルと違っても、**入力→操作UI→状態→演出という共通因果**を比較する。
4. **操作中の上画面可視性を改修する前に**、ラウンド途中のホスト行動/ゲストスナップ/タッチ受付をブラウザ2窓でQAできるシナリオを用意する。
5. **原作対戦の順序・モーション表示遅延**は他の動画・研究記事・2視点同期が必要。完全一致を急いで宣言しない。若干の実装違いで戦術が変わるので特に高優先。
6. 改善をコード化する際は**変更前にテスト例**（原作の操作フロー・視認性・イベント順）を決める。学内Google Sites公開版・GitHub main・Firebase本番Rules/DBは勝手に触らない。

## 次の調査に残る具体的な疑問
- 原作のチャージ中に上画面が見えているのは確認済。**自分のサークル回転**はチャージ/おはらい中に受け付けるか？相手の操作はどう映るか？
