## 原作で確認できた範囲と研究フィクスチャの区別
- [ゲームエイト 妖怪ウォッチ2 必殺技の使い方](https://game8.jp/youkai-watch2/504498)には、妖気ゲージ満タンでわざOK→タッチ操作チャージ→技を発動する流れ、4種類「まわせ」「打て」「なぞれ」「あわせろ」が記載。今回の正規ホストは既存`engine/charge-input.mjs`で4パターンとも扱う。ただし閾値、ミニゲームの選択確率、必要タップ数、制限時間は元資料では確定せず、**研究フィクスチャ**のまま。
- [攻略大百科 G技](https://gamepedia.jp/youkai-yw2/archives/1873)・[攻略大百科ウバウネ攻略](https://gamepedia.jp/youkai-yw2/archives/5657)：零式G技は発動妖怪だけでなく**固定輪の左右隣2体も妖気満タン**である必要がある。後衛にいる隣接妖怪も対象となる。現行`engine/soul.mjs`は輪の元順で隣接を管理。
- [妖気自然回復・チャージの解説](https://gamepedia.jp/youkai-yw2/archives/1482)：満タンまでの正確な行動時・時間ベースの蓄積レートは未証明。通常ホストの「非攻撃+5」は前段Phase21Dで研究者の条件付き実験に照合済みだが、攻撃/妖術/つつくの妖気量は依然原作未検証。
- 初期レンタルキャラは本家そのままの妖怪ではない。技の基礎効果`researchSpecialEffects:false`を指定したテストでは、実装されていない原作必殺ダメージを確定扱いしない。

## 実装
**新規**`tests/phase22b-canonical-soultimate-qa.test.mjs`（正規ゲーム/正規ホストの既存APIのみ。debug giveSoul等は禁止）：

1. **4チャージ種×4試験**：seed1 `align`、seed2 `tap`、seed3 `trace`、seed4 `spin`。各々 `createMatchProtocol()`で、自律行動を進めてA1が満タン→標準モードでわざ開始→実際の正規`chargeInput`（座標指示に基づくdown/move/tap/up）で完走→本人の妖気全消費→二度目の同じ通信パケットを送っても妖気二重消費なし→まだ妖気が空なら再チャージ不可→次の正規行動で再チャージ可能→`replayMatchJournal`のSHAではないQA state fingerprint一致。
2. **途中ウォッチ切替**：既にチャージ中の妖怪に標準→零式を行うと、ミニゲーム中止、妖気は残る。中止後の古いタッチは拒否、標準へ戻すと開始可。
3. **輪を回して後衛化**：チャージ中の本人を後衛へ戻すとチャージだけ中止、妖気は残る。前衛に戻した後再開可能。
4. **零式G技**：A6・A1・A2に通常のガード行動で妖気を貯め、輪を元に戻して**A6が後衛**のままA1のG技を始める。固定輪の左右A6/A2が選ばれていることと、チャージ完了時に3体分の妖気を使い切り、隣でないA3は消費されないことをテスト。
5. **通常100ゲージ**：4ケースのスピードアップのためSoul容量5という意図的な調査用能力値を使うが、それとは別に容量100のレンタル戦で、非攻撃行動による実正規回復→わざOK→チャージ→100消費→replayを実行。
6. **正規ホスト両席**：ホスト側Aと相手Bで同時にチャージ開始・それぞれの指入力で完了させ、片側終了時点でも他方の妖気とチャージは維持されることを検証。連続通信イベントを含む再演が一致。

`makeStageView()`と`soultimateReadiness()`を直接照合し、UIの選択可能表示が実際のホスト前後で消費・チャージ中状態と整合するか検証する。

**重要:** テストはゲームの正規`createMatchProtocol`インターフェイスを通るが、**容量5などの制御条件や研究用ミニゲーム座標は本家と同一の実ゲーム設定ではない**。ユーザー向けUIを手動で操作した学校Safari確認や、本番Firebaseに接続した実機試験とは別。オンラインホストにデバッグコマンドを追加しない。
