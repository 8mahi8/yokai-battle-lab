## これを現在の実装に照らすと何が足りないか
1. **入力中の上画面を遮るフルスクリーン・モーダル**：`ui/match-stage.mjs`は`#mb-modal`でジェスチャーを実行し、`lab/match-stage.css`は`position:fixed; inset:0; background:#081019df`。原作0:15–00:18、01:11–01:21で「上画面の情報を見ながら下画面操作」という体験が見える。再現は下画面の範囲に収まる操作ビューが必要。
2. **おはらい完了シーン**：`engine/combat.mjs`に`type:'purification'`はあるが、`ui/battle-vfx.mjs`/`ui/battle-cue-sequence.mjs`は`action/special/poke`だけで、単独の完了モーションは演出されない。00:18、01:15、01:21のような下画面/上画面の切替フィードバックを比較する。
3. **照準**：0:32–0:38で上画面の円形リング+赤十字と下画面のレンズが同期する。現在の`pin`や`pokeStart`のボタン→単純対象選択とは一部手順・演出が違う。
4. **複数ヒット**：00:47–00:51、01:33–01:35のように**時間が離れた個別ヒット**を見せるべき。現在`presentation/action-choreography.mjs`は`special`の全impactを単一の同じimpact開始境界で表示。
5. **技固有のカットイン**：同じジバニャンでも別イベント、トホホと大ガマはポーズ・色・背景が全く異なる。現在の共通`special`フレームワークはデータ駆動で技名と絵を分けるべきだが実装未完。
6. **勝敗までのアクションや画面遷移の整合**：勝敗オーバーレイがあるだけで原作の場面転換一致とは言えない。

## 観測不能なもの
- 指が画面に映っていない → 何回連打したか、回転の方向、入力フレーム、指の移動距離。
- 別画面で同時に何が起きたかの録画がない → **相手視点の表示保留**やノーモーション成立の確定。
- 実ゲームの生ログがない → 内部RNG確率、技の正確なチャージ閾値、時間クロック、当たった各ヒットの公式ダメージ式。
- 現ソース動画の複数フレームはフィールド・字幕のオーバーレイや画面小さい部分がある → 解像度の制約を明記。
